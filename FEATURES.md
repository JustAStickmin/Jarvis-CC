## Chat Commands

Type any of these in Minecraft chat within range of the chat box.

### General

| Command | What it does |
|---|---|
| `jarvis` | Greets you with a random response |
| `jarvis time` | Reports current in-game time + period |
| `jarvis day` | Reports the day number since world creation |
| `jarvis status` | Reports all systems nominal (system check) |
| `jarvis threat` | Random threat-level read-out |

### Fun

| Command | What it does |
|---|---|
| `jarvis joke` | Tells a programming/dad joke |
| `jarvis quote` | Famous historical quote |

| `jarvis compliment` | Compliments you |
| `jarvis roast` | Roasts you |
| `jarvis warn` | Random absurd "WARNING" |
| `jarvis diagnose` | Mock diagnostics readout |
| `jarvis flip` | Coin flip |

## Monitor Display System

JARVIS drives seven monitors simultaneously via wired modems. Each monitor's role is configured in `config.txt`.

| Role | Suggested size | What it shows |
|---|---|---|
| `help` | 5×4 | Command list (or "TBD" placeholder on pages 1–15) |
| `face` | 5×4 | Animated JARVIS HUD: spinning rings, scanning line, status |
| `energy` | 3×2 | AE2 energy meter, drawn as a battery |
| `lights` | 1×1 | "[ ON ]" / "[OFF]" indicator |
| `storage` | 1×4 (portrait) | AE2 storage fill bar with stats at the bottom |
| `last` | 4×1 (wide) | Most recent thing JARVIS said + timestamp |
| `clock` | 4×1 (wide) | In-game time + period (Night/Sunrise/Day/etc.) + day-night bar |

All monitors auto-scale to fit their physical dimensions. Monitor assignments are autogenerated on first run (`labels` to identify, `edit config.txt` to remap).

### HUD animation (`face` monitor)

- Five nested rings drawn with directional ASCII (`-`, `|`, `/`, `\`, `.`, `:`)
- Rotating orange arc (clockwise) and counter-rotating lightBlue arc on opposite side
- Counter-spinning inner orange arc on the third ring
- Clock-position tick marks on the outer ring
- Pulse animation that grows the outer ring while JARVIS is speaking
- Sweeping cyan scan line across the center while speaking
- Corner brackets in cyan
- Center text shows "J.A.R.V.I.S." + "[ ONLINE ]" / "[ SPEAKING ]" + current time

### Clock periods

Time periods on the clock monitor: Night → Predawn → Sunrise → Morning → Noon → Afternoon → Sunset → Dusk → Night, color-coded.

## Audio System

Speaker melodies are pre-composed note sequences played via the speaker peripheral:

- `fanfare` — triumphant rising melody
- `alarm` — alternating bass drum / snare
- `startup` — short ascending notes + bell (played at boot)
- `music` — multi-bar flute melody
- `sad` — descending minor notes (played at shutdown)
- `victory` — celebratory bell sequence

The `play <sound>` command can play ANY Minecraft sound ID directly via `speaker.playSound`.

## Redstone Controls

Three redstone integrators, each driven by a distinct role in `config.txt`:

| Role | Type | Behavior |
|---|---|---|
| `light` | digital output | Toggles ON/OFF with `jarvis lights`. Drives a redstone link → all your base lights |
| `talk` | digital output | Goes HIGH the moment JARVIS starts speaking, LOW ~2 seconds later when the message has been read. Drive a piston, note block, beacon, anything pulsing |
| `scroll` | numeric input | Reads a 0–15 value from a CC:Create Bridge scroller pane (or any peripheral exposing `getValue` / `getScrollValue` / `getAnalogInput`). Picks the help page shown on the help monitor |

The scroll integrator's range is auto-constrained on startup: `setLimit(15)` is called and the minus spectrum is disabled, so values stay clean at 0–15.

## Help Page System

The help monitor has 16 pages, switched by the scroller:

- **Page 0** — live command list (the actual help screen)
- **Pages 1–15** — "TBD" placeholders inviting users to suggest content via the JARVIS Discord thread

The current page number is shown as `[ N ]` in the bottom-right corner of the help monitor.

`jarvis page <n>` overrides the scroller for manual testing.

## Satellite Network

JARVIS communicates with separate satellite computers over rednet via ender modems. Each satellite runs its own `satellite.lua` + per-role animation module.

### Architecture

- Protocol: `"jarvis"` rednet protocol
- Discovery: satellites broadcast `{type="hello", role=..., id=...}` on boot; main JARVIS broadcasts `{cmd="ping", target="all"}` on boot to wake them up
- Commands: main sends `{cmd="toggle"|"on"|"off", target=<role>}`; satellite filters by its own role
- Per-satellite config: `satelliteconfig.txt` declares the satellite's role and which monitor to use

### Available satellite roles

- **`campfire`** — animated campfire with four states:
  - `burning` — flickering flames, rising sparks, glowing embers in the logs
  - `dousing` — water drops fall, splash into steam, fire shrinks
  - `doused` — dim wet logs, drifting smoke
  - `lighting` — flames grow back up from sparks (reverse of dousing)

Adding new satellite types is just dropping a `satellites/<role>.lua` module in the repo that exposes `init(mon)`, `draw()`, `toggle()`, `setOn()`, `setOff()`.

## Configuration System

### `config.txt` (main computer)

Plain-text format, autogenerated on first run by detecting hardware. Lives locally on each CC computer (not committed to git). Edit with `edit config.txt`.

Sections:

- **Monitors (main)** — `role: peripheralName, WxH` per monitor
- **Peripherals** — chatBox / meBridge / speaker overrides
- **Redstone** — light / talk integrator names
- **Inputs** — scroll peripheral name

Run `labels` in-game first to see each monitor's peripheral name.

### `satelliteconfig.txt` (satellite computers)

Same format, much smaller. One line under `-- Monitors (satellites) --` declaring the role and the monitor name.

### Persistence

- Configs survive `update` (the updater only fetches code, never overwrites configs)
- Configs survive CC computer restarts (saved in the world)
- Delete a config to regenerate from autogen

## Utilities & Debug

| Program | Purpose |
|---|---|
| `update` | Pulls latest code from GitHub for the JARVIS repo |
| `labels` | Flashes every monitor's peripheral name + size on the monitor itself |
| `main` | Launches JARVIS on the main computer |
| `satellite` | Launches a satellite on a satellite computer |

### In-chat diagnostics

- `jarvis config` — short summary of current monitor assignments
- `jarvis pdebug <name>` — full type + method list for any peripheral
- `jarvis satellites` — list of online satellites by role

### Startup diagnostics (terminal)

JARVIS prints at boot:

- Loaded config.txt entries (one line per role)
- WARNINGS if any configured peripheral name doesn't resolve
- Detected monitor list with sizes + shape classification
- Final role → peripheral assignments, tagged `(config)` or `(auto)` so you know which came from where
- Scroller initialization state (limit applied, current value)
- Satellite discovery events as satellites come online
